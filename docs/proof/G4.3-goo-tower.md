## 1. Carry-over from G4.2 — the 150 ms probe (R22): **fixed**

- **Cause (measured):** UTP's desktop `WebSocketLayer` gives the HTTP upgrade **one final timeout equal to `ConnectTimeoutMS`** (1000 ms, no retry). Through the netem relay a single lost segment costs Linux's 1 s initial RTO, so the upgrade misses the deadline (`MaxConnectionAttempts` after ~2 s; socat shows one TCP connection per client). Reproduced: 1 of 3 failing at 2 % loss; 6 / 6 connecting at 0 % loss.
- **Fix (dev scripts + client connect timeout only):** probe clients pass `-fallrushConnectTimeoutMs 4000` (`scripts/m2-probe.sh`, read in `NetBootstrap.ConnectRoutine`); clients start 2 s apart (`m3-gate.sh`); the relay retries `apk add` (one run failed on a flaky package fetch). The shipped `NetClientConfig` (1000 ms × 10) is unchanged — WebGL's `WebSocketNetworkInterface` already allows timeout × attempts = 10 s. No server or protocol change.
- **Capsule Run re-measured at 150 ms ± 15 + 2 % loss** (commit `b7a0fc5`, G4.2 proof §8): all 3 clients connected; racing non-push corrections **0.08 / 0.42 / 0.00** per 5 s, hazard mismatches **0 / 0 / 0**. Client 2 is 0.02 over the 0.4 target (parked with the Capsule Run items for G4.7).
- One later Goo Tower 150 ms run had all three clients closed gracefully right after connecting (`ProtocolError`); the immediate rerun connected 3 / 3. Recorded as intermittent.

Deterministic for a run seed: yes. **QA PASS** (the harness criteria: valid result, no soft-lock, qualified ≤ target, goo never overtakes a route, determinism).

Against the G4.3 targets:
- 0 free routes, ratios ≤ 1.25, hit and fall bands — **met**.
- Every route index escapes alone — **met**; min margin 8–10 s — **met on 5 of 6 indices; A route 0 is 6.5 s**.
- **Exactly 5 of 8 escape every run — not met** (reference 4.9–5.0, normal 4.1–4.3 on average).
- **Normal median 90–110 s — not met (59 s).** Reference bots ≤ 5 falls per round — met (falls on this map are lap drops; route QA ≤ 0.63 per side traversal).
- Determinism — met.

**Why, and the options (your call):** a reference climber takes ≈ 50 s alone, and the 8–10 s fairness margin pins the goo to the start (the minimum margin is always at the bottom, where everyone begins), so the goo covers lap 1 by ≈ 40–80 s. On lap 2 (open edge) a fall lands on a lap-1 side that is already under the goo, so most lap-2 knock-offs eliminate; normal bots fall off k4 / k5 often enough that 3–4 of 8 are gooed, and the round ends when the last climber is out (59 s), not at the 5th escape. Options:
1. **Lap-2 catch ledges** (a 1 m lip, or a net one lap down): lap-2 falls become a time loss instead of an elimination → 5 escape, but the round gets *shorter*. Changes rule "lap 2: no outer rail".
2. **More climb per lap** (a longer, slower climb so the median reaches 90 s): the 14 m core gives 19 m per side; reaching 90–110 s needs roughly twice the waiting (longer lift / door / mallet cycles) — doable, but the goo would then cover lap 1 while normal bots are still on it.
3. **Accept a 55–65 s survival round** and revise the GDD target for Round 2 (Capsule Run is 86 s; a short climb round after it reads as a change of pace).
Rules 2–4 (chain, determinism, movement) are untouched by all three.
