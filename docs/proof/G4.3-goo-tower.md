## 1. Carry-over from G4.2 — the 150 ms probe (R22): **fixed**

- **Cause (measured):** UTP's desktop `WebSocketLayer` gives the HTTP upgrade **one final timeout equal to `ConnectTimeoutMS`** (1000 ms, no retry). Through the netem relay a single lost segment costs Linux's 1 s initial RTO, so the upgrade misses the deadline (`MaxConnectionAttempts` after ~2 s; socat shows one TCP connection per client). Reproduced: 1 of 3 failing at 2 % loss; 6 / 6 connecting at 0 % loss.
- **Fix (dev scripts + client connect timeout only):** probe clients pass `-fallrushConnectTimeoutMs 4000` (`scripts/m2-probe.sh`, read in `NetBootstrap.ConnectRoutine`); clients start 2 s apart (`m3-gate.sh`); the relay retries `apk add` (one run failed on a flaky package fetch). The shipped `NetClientConfig` (1000 ms × 10) is unchanged — WebGL's `WebSocketNetworkInterface` already allows timeout × attempts = 10 s. No server or protocol change.
- **Capsule Run re-measured at 150 ms ± 15 + 2 % loss** (commit `b7a0fc5`, G4.2 proof §8): all 3 clients connected; racing non-push corrections **0.08 / 0.42 / 0.00** per 5 s, hazard mismatches **0 / 0 / 0**. Client 2 is 0.02 over the 0.4 target (parked with the Capsule Run items for G4.7).
- One later Goo Tower 150 ms run had all three clients closed gracefully right after connecting (`ProtocolError`); the immediate rerun connected 3 / 3. Recorded as intermittent.

**Why the round is short, and the options (your call):** a clean climb of the 152 m path takes ≈ 45–50 s at 5 m/s with the hazard waits, and the crowd passes the timed hazards in parallel (two lanes, two lifts, three doors), so longer cycles add little: G4.3d tried lifts up to 260 / 290 ticks, door cycles 300 / 420, mallets 250 / 340 ticks and a faster belt — the normal median moved 57 → 67 s at best, and it put lift 0 at 1.42×, the k6 belt at 1.40×, door 2 at 1.29×, the k5 inner arc at 2.7× and one goo margin at 7.5 s. Those steps were reverted. Options:
1. **Accept a 50–65 s Round 2** and revise the GDD target for it (Capsule Run is 86 s; a short, tense climb reads as a change of pace).
2. **A third lap or a bigger core** (more path): the most direct way to 90 s; a larger rebuild (a 30 m tower, or 18–20 m sides), the plan page would change.
3. **A slower goo + gates that hold the crowd** (e.g. a full-width timed gate on each lap): longer, but it adds waiting rather than climbing.
Rules 2–4 (chain, determinism, movement) are untouched by all three.
