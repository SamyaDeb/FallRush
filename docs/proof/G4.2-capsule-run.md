- **R22 cause and fix (G4.3 carry-over, 2026-11-20, measured):** UTP's desktop `WebSocketLayer` gives the HTTP upgrade **one final timeout equal to `ConnectTimeoutMS`** (1000 ms, no retry; `WebSocketLayer.cs` state `Opening`). Behind the relay each direction is delayed 75 ± 15 ms and 2 % of segments are lost, so one lost segment in the upgrade costs Linux's 1 s initial RTO and the connect fails within ~2 s (socat log: one TCP connection per client, closed after 2–4 s). Fix, dev only: probe clients pass `-fallrushConnectTimeoutMs 4000` (`scripts/m2-probe.sh`, read in `NetBootstrap.ConnectRoutine`), clients start 2 s apart (`m3-gate.sh`), and the relay retries its `apk add` (one run failed on a flaky package fetch).
