# P7 decisions (OC-29 …), copied into doc 15 at the end

| ID | Decision (options · numbers · choice · why) | Revert |
|---|---|---|
| OC-29 | **D-POLISH: our own tween layer + one card builder.** `UiMotion` (curves, pure, tested) + `UiAnim` (one component per target, unscaled time, allocation-free per frame; positional motion is an offset re-applied in LateUpdate, rows animate a non-layout "Face" child) instead of a package (no new packages allowed). `UiKit.MakeCard` (soft shadow, saturated rim, pastel body from `PaletteTokens.SoftTopHex`, 2-tone bevel, rim ribbon with icon + outlined display title, S/M/L) is used by every match screen and the economy HUD; plain panels (`UiKit.Panel`) became soft cream panels with a lavender rim. Reduced motion → fades only. | `git revert` the P7 UI commits; `UiKit.Panel` back to `Chunk` |
| OC-30 | **D-GLYPH: a procedural UI icon atlas, never emoji fonts.** The static font chain (Lilita One / Varela Round + Noto Sans Symbols 2) lacks 🌀 👑 ⚠ → − ≈ ² (found by scanning every UI string literal against the font assets' character tables). Emoji became `UiIcons` sprites (crown, swirl, lock, warning, capsule, check, cross, race / survival / skill / final, chip, link, eye, trophy, bolt, ring: signed-distance shapes in one 384² texture, our own crown design); the text symbols became covered characters. An EditMode test fails on any uncovered character in Client / OnChain string literals. | delete `UiIcons.cs`, restore the strings |
| OC-31 | **Dev clean-up: `DevMenu` = Editor / development build / `?dev=1`.** Practice / tuning, the G4 sandbox, the Feel Lab, the wallet smoke test, server URLs and the on-chain-only entry are hidden in release unless `?dev=1`. "Play On-Chain (preview)" plays the on-chain Final alone (the public flow plays the hybrid match from Play), so it is renamed **"On-chain Final only (dev)"** and stays dev-only. "Enter Sandbox (M2)" → "Enter the arena". `WebGLTemplates/xNFT` deleted (unused: the template is Default). | `DevMenu.Enabled => true` |
| OC-32 | **Honest deal / practice labels.** The public Classic server runs its matches with the practice flag and a local seed; the arena keeper records them on-chain. The HUD now treats a match as practice only when no on-chain layer runs (`MatchHud.RecordedMatch`, set by the economy HUD). The Deal chip says "Rounds 1–3: Classic deal (game server seed)", and once the keeper's `request_deal` lands (`/api/status` → `keeper.dealSig`) "VRF ✓ MagicBlock VRF seeds the on-chain Final" with a "View the VRF request" button: the VRF seed drives the on-chain Final (`start_final`) and the capsule seed, not rounds 1–3. | keeper / indexer `dealSig` lines; HUD strings |
| OC-33 | **Bug: the bet panel covered alive players in rounds 1–3.** The pre-joined on-chain session has no slot before the Final, so `spectating` was true for everyone and the panel opened over the race (P6 build, before-shot 05). Now: rounds 1–3 → auto-open only for players who are out (Classic slot not alive) or not in the match; the Final → eliminated players / watchers; an alive player opens it with B (a "B: open Rush Markets" chip shows when markets are open). | `EconomyHud.Update` spectating line |
| OC-34 | **Bug: P6 match 3's first-tick replay mismatch = the Final's map-load tick.** The program's `tick()` runs `director::needs_map → load_round` before stepping on the Final's tick 0 → 1; `rush_core.wasm`'s per-tick `rc_step` does not load maps. Archives that start at tick 0 (match 3) failed only that pair; archives that start later (most) never had it. The verifier (web `lib/verify.ts`, `tools/p7/replay-check.mjs`) now starts after the map-load tick and says so. Match 3 (2 humans): **2728/2728 byte-exact, transcript ✓** (was 2728/2729). rush-core / the wasm unchanged. | the two `mapLoad` lines |
| OC-35 | **Bug: "the `?autobet=` hook fires twice" = two hooks.** `OnChainAutoPlay` (`?onchainauto`) bets every open market including market 0, and on a sealed Champion that is a sealed bet, while `?autobet=` places its own. Now `?autobet=` owns the Champion (`AutobetOwnsChampion`), and both wait for `ChipsReady` (a fresh guest's first bet failed with Anchor 3007 before its chips account reached the rollup). Also fixed: `ChainEconomy.Update` threw "Collection was modified" every time a callback queued the next call (live build console, 4× per page load). | revert the two guards |
| OC-36 | **D-RPC: 429 backoff in the chain bundle.** The public devnet RPC 429s when many clients share one IP. web3.js's own retry stays off; the bundle's `fetch` retries a 429 with exponential backoff + jitter (≈ 0.4 / 0.9 / 1.8 / 3.2 s, +0–40 %, Retry-After honoured, ≤ 4 tries) and counts them (`rpc429`). Base sends stay behind the 1.5 tx/s token bucket. No paid RPC. | `web3conn.ts` back to the plain Connection |
| OC-37 | **Judging-week watchdog = a host systemd timer `fallrush-watchdog`** (not a container: no Docker socket mount into a container). Every 60 s: container state/health + `/api/status` (gs1/gs2 up, indexer ok) + keeper `/health`; restarts only a fixed list of `fallrush-*` containers after 3 consecutive failures; `CPUQuota=10 %`, `MemoryMax=64M`; log `/opt/fallrush/logs/watchdog.log` self-rotated at 1 MB. | `systemctl disable --now fallrush-watchdog.timer`, delete the two units |
| OC-38 | **Waitlist CORS redeploy denied by the permission system (again).** Not worked around; the exact command is in `docs/prompts/P7-USER-STEPS.md` → "Run these yourself" (W1). | — |

| OC-40 | **D-CHAOS fix: a Classic server restart mid-round blocked the arena.** The keeper's bridge waited up to 30 min for events from a log that had stopped (no END / ABORT), so the on-chain match stayed open and the arena recorded nothing. The stuck match from the test was aborted on the redeploy with every market refunded (paid = pool, label aborted). | `bridgeRounds13(…, classicGone)` param |

| OC-44 | **P7-UX (user, 2026-11-24): in-match UX rework.** Playing the public build, the user found the Rush Markets card forced open over the match for every eliminated player (`betVisible = _betOpen \|\| (anyOpen && spectating && !finalRush)`), B unable to close it, and the pointer re-locked by any click (so nothing could be clicked). | OC-46 | **Private rooms (user pick: an idle arena, else a Classic-only server; one arena always stays public).** Hello v7 carries a room code + skill tier (a v6 client gets the existing "reload" message). The indexer's `POST /api/room` reserves an idle server and writes `ROOMS/<gs>.json`; the server polls it every second: only that code is admitted (a code for a room that is not there is refused too), no auto countdown, the host's START begins the match, bots fill to 12 (same roster shape as public, so the keeper / program see nothing new). Rooms expire 10 min unused / 5 min after the last human; a restarted indexer clears them. The Classic-only room server `fallrush-gs3` (no arena, no keeper) rides on the gs1 name at `/gs3` (no new certificate). | `ROOMS_ON=0` on the indexer (kill switch, the hub hides rooms) |
| OC-47 | **Skill tiers + bot difficulty (user pick).** Tier from this browser's history: score = crowns × 10 + Finals × 4 + rounds survived; Rookie < 15 ≤ Contender < 60 ≤ Champion (UNVERIFIED thresholds). `POST /api/mm` prefers a same-tier public lobby, then an empty server, then the nearest tier. The lobby's tier (most common among its humans) sets the bots' mix, still a pure function of the seed: Contender = the M4 rule exactly (tested), Rookie 60/35/5 %, Champion 10/45/45 % easy/normal/good. A forged tier only changes the bots' mix and grouping. | `MM_ON=0`; `TierFor(seed, slot)` again |
