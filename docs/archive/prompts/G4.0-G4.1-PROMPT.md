## 1. Non-negotiable rules

2. **Seeds stay one-line swappable to VRF.** Every random choice derives from the per-obstacle seed that `HazardResolve` already produces (today `FNV-1a(seed_le8 ‖ obstacleId)`; in M6 `H(vrf_seed ‖ round ‖ obstacleId)`). ## 4. G4.1: hazard kit additions (≈ 4 h)

### G4.1a ROLLING_BALL
- `RollingBallDef` (Shared, integers): `StartMm` (x,y,z), `EndMm` (x,y,z), `RadiusMm` (allow 600–1200), `SpeedMmS` (2 000–7 000), `PeriodTicks` (release interval, 30–300), `Phase16`, `TelegraphTicks` (default 15), `KnockProfile` (use the mallet's knock_hard constants).
- Pose: ball k is released at `t_k = k·PeriodTicks − phaseOffset`; its travel fraction is `(t − t_k)·SpeedMmS / (30·len)` in integer maths (precompute `len` in mm at load with an integer sqrt). Several balls per lane can be alive at once (`ceil(travel / period)`); evaluate only those whose window covers `t`. Position = integer lerp start → end. A ball past the end despawns (no collider).
- Contact (`RollingBallContactMm`): sphere vs. the player capsule in integer mm (follow `MalletContactMm`). Push = roll direction, plus the lateral offset component normalised (float only here). Applies stun and immunity like the mallet. Players can't stand on a ball: it is a knock volume, not a surface.
- Telegraph helper (pure): `RollingBallTelegraph(def, t)` → 0…1 for the chute light in the `TelegraphTicks` before each release.
- Wire it in: `HazardSet.RollingBalls` array; `PlayerStep.Run` knock phase, after mallets and sweepers, same immunity rules; `HazardAllowlist.Check(in RollingBallDef …)` with the ranges above plus "the path must not start inside a spawn volume"; `HazardResolve.SetPhase`; `HazardAuthoring` + a `HazardRollingBall` view (MonoBehaviour, own file) that only *renders* the pure pose (with spin from the travelled distance).

### G4.1b LID_FLIP grid with ring retire
- `LidGridDef` (Shared, integers): `OriginMm`, `N` (odd, 5–11), `LidMm` (1 200–2 200), `GapMm`, `TopMm`, `ThicknessMm`, `LitTicks` (30), `FlippedTicks` (45), a wave schedule (`WaveIntervals` e.g. 90 / 75 / 60 / 45 ticks with `WavesPerStage` 8), `FlipCounts` per stage (lids flipped per wave as a share of alive lids, e.g. 20 / 25 / 30 / 35 %), `RingRetireTicks` (e.g. 750 / 1500 / 2250, i.e. every 25 s at 30 Hz), `RetireWarnTicks` (90), `MinInnerSolid` (≥ 5 of the inner 3 × 3 solid at every tick).
- **Pure state** `LidState(def, seed, lidIndex, t)` → `Idle | Lit | Flipped | Retired | RetireWarn`:
  - `Retired` if the lid's ring (Chebyshev distance from the centre) has a retire tick ≤ `t`; `RetireWarn` in the `RetireWarnTicks` before it.
  - The wave start ticks are a closed-form piecewise sum of the stage intervals (no loop over all past waves). For wave w, the flipped set = the first `k(w)` lids of a seeded partial Fisher–Yates permutation of the lids **alive at that wave's start**, with seed `mix(obstacleSeed, w)`. A lid is `Lit` in `[start(w), start(w)+LitTicks)` and `Flipped` in the following `FlippedTicks` for any wave w whose window covers `t`; check only the waves that can (at most `ceil((Lit+Flipped)/minInterval)`).
  - **Fairness:** if a wave would leave fewer than `MinInnerSolid` inner lids solid at any tick of its window, drop inner lids from that wave in permutation order until it holds. Enforce it in the function, not in the builder.
  - Cost: O(waves checked) per lid per tick. No allocation (use a fixed scratch buffer of N² sized at load).
- **Colliders:** each lid's collider is on in `Idle | Lit | RetireWarn` and off in `Flipped | Retired`, **posed from the tick** in `PhysxMotorWorld` exactly like gate doors, on the server and in client prediction and rewind. No reactive replication and no new network messages.
- View: `HazardLidGrid` (MonoBehaviour, own file) renders state from the interpolated server tick: lit = yellow pulse, flipped = a 180° flip animation over 6 ticks, retire warn = blinking, retired = drop away. Visual only.
- Keep `TileGridDef` / `HazardCrumbleGrid` / `ReactiveSet` untouched (the fallback per `G4-PROMPT` §2.4).
- **M6 note:** the flip pattern seed is the per-obstacle seed, so in M6 it becomes `H(vrf_seed ‖ round ‖ obstacleId)` with no code change in the grid. Write this in "Notes for M6": the Final's floor pattern is then derived from MagicBlock VRF, and the receipt can show it.
