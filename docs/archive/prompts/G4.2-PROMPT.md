## 3. Steps

### G4.2a Builder rewrite (≈ 3 h)
- Rewrite `BlockPartyDashBuilder.cs` to §2. Keep it code-built and re-runnable (`Fall Rush/Setup/Build Map_BlockPartyDash`, batch `-executeMethod BlockPartyDashBuilder.Run`), the `Geometry` / `Hazards` roots, layers, kill-Y, checkpoints (`RaceCheckpoint`, 12 respawn spots each) and the finish.
- Hazard ids stay unique and stable (`bpd_s1_ball_0…4`, `bpd_gate_door_0…4`, `bpd_gate_xball`, …): the per-obstacle seed is derived from them.
- `HazardAllowlist` must accept every def; fix the def, never widen the allowlist to pass.
- Update `MapDressing.BlockPartyDash` and the `Bpd*` art in `MapArt.cs` to the new geometry: props stay outside every gameplay volume, nothing floats over removed geometry, and the old title sign and route labels are gone.

### G4.2b Bots that can run it (≈ 2 h)
- `BotBrain` `WaitClear`: also predict **ROLLING_BALL** positions along the straight path to the next point over the next ~1 s (pure pose, so bots see only what a player sees), the same way it treats spinner bars and mallets. Add a `WaitAction`-style hesitation for the Wave Gates using the existing `Door` action.
- New `Routes()` per section (section = checkpoints reached). Every route must be reachable by reference **and** normal bots:
  - S0 start → CP1: at least three slope routes between the ball lanes (dodging by timing).
  - S1 CP1 → CP2: Wave Gates door 1…5 (via `Door`) × Hop Field centre / left / right.
  - S2 CP2 → CP3: Sweep Pad left arc / right arc (jump the low arm, dive the high arm).
  - S3 CP3 → CP4: Mallet Run (one route, `WaitClear` before each mallet).
  - S4 CP4 → finish: belt left / centre / right through the bumpers, and spring left / right.

### G4.2c QA and tuning loop (≈ 2–3 h)
Run `scripts/g4-route-qa.sh 100 BlockPartyDash docs/proof/g4/route-cost-after.md`, then `scripts/g1-qa.sh 100 BlockPartyDash` and `scripts/m4-qa.sh 100` (Race), and tune until **all** of these hold for both variants and every allowed modifier (None, MoonBounce, ButterFloors, TurboToys, TinyTilt):

| Check | Target |
|---|---|
| FREE ROUTES | **0** (every route has hazard hits or door push-outs with normal bots) |
| Route cost per section | slowest valid route **1.00–1.25×** the fastest (single-route sections exempt) |
| Hits per route (normal bots) | ≥ 10 per 100 traversals; no section where normal bots average > 1.5 falls per traversal |
| Reference bots | ≤ 5 falls per race on average; every route reaches its next checkpoint |
| Soft-locks / blocked ticks | 0; never a tick where every door is closed |
| Qualify | exactly 8 of 12 in every run |
| Normal-bot median | **85–110 s** (today 88.4 s on 250 m) |
| Determinism | same run seed → same result |

Tuning levers, in this order: release periods and speeds, door timings, mallet / sweeper periods, gap widths within the movement-v2 rules, bumper positions. Don't change movement or the qualify rule. Keep every tuning step in a before → after table.

### G4.2d Tests, guard, docs (≈ 1 h)
- `BlockPartyDashTests`: the full race with 12 waypoint bots → 8 qualified, ordered (both variants); new tests: **no text components** in the scene under `Geometry` / `Hazards` / dressing; **each section has at least one knock hazard** whose sweep volume intersects the section's z range; every section index 0–4 has ≥ 1 route; the map key / id / variant count are unchanged.
